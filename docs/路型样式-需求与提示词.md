# 轨迹路型样式 —— 需求与提示词（待确认）

> 目标：在 TrailProfile 的轨迹线上增加「路面类型」分段表达，比单色线条更有信息量与质感。
> 状态：**待用户确认后再动代码**。本文档即施工提示词。

---

## 1. 一句话需求

轨迹不再是一条统一的线：可按「A 途经点 → B 途经点」（或按里程）指定某段是**机耕路 / 土路 / 步道台阶 / 陡坡山路 / 攀爬**，用**线宽 + 纹理 + 轻微色相**三种手段同时表达；并可选在底部里程轴上给一条路型条带，跟随生长进度点亮。

---

## 2. 视觉语言（核心）

### 2.1 五种路型定义

| 路型 | 线宽权重 | 主色 | 纹理 | 观感目标 |
|---|---|---|---|---|
| 机耕路 | 1.25× | `#8B6B4A` 土棕 | 双线（车辙）：宽底线 + 偏移 3px 的高光短虚线 | 宽、硬底、有车辙 |
| 土路 | 1.00× | `#A98467` 沙褐 | 颗粒：细浅色点线叠加（1 亮 5 暗） | 中等、表面松散 |
| 步道台阶 | 0.90× | `#6B7A8F` 石灰 | 法向短杠：沿弧长每 N px 画一条垂直短线，超出线宽 ±3px | 等距踏步 |
| 陡坡山路 | 0.75× | `#BA7517` 橙 | 碎点：1.4px 短虚线密排 | 细、崎岖 |
| 攀爬 | 0.60× | `#A32D2D` 红 | 断续点：3 亮 8 暗圆头点线 | 最细、需要手脚 |

- 纹理全部用 `stroke-dasharray` 实现，**只有「台阶」的横杠需要沿路径算法向（逐点算切向 → 法向 ±offset → 输出 line 图元）**，其余都是纯 dash。
- 色相强度可调（`路型色相强度` 0~1，默认 0.85）：调到 0 = 全部用轨迹主色，只保留宽度与纹理差异，适合极简风。

### 2.2 已走 / 未走必须同纹（★关键）

现状：未走 = 半透明灰，已走 = 白色实线盖上去。若照搬，纹理在走到之后就消失了。

规则：
- **同一段路画两遍**：底层「未走态」= 主色压暗 45% + 不透明度 0.42；上层「已走态」= 主色提亮 55%。
- 两层用**同一套纹理参数**，只是颜色不同 → 纹理在两种状态下都可读。
- 已走裁剪不能再用整条 path 的 `pathLength=1`（分段后就乱了），改为**逐段独立 path**：
  - 每段 `pathLength=100`
  - `strokeDasharray = "${p} 100"`，`p = clamp((distM - segStart) / (segEnd - segStart), 0, 1) * 100`
  - 段边界处 `strokeLinecap="round"`，相邻段起点回退 0.5px 防缝隙。
- 光晕层保留，但改为「已走段的主色光晕」，不再用统一白色。

### 2.3 三层呈现

**第 1 层 · 地图笔触**（默认开）
轨迹按分段换笔触，几何位置完全不动（只变笔宽/纹理/颜色），不伪造地形。

**第 2 层 · 底部路型条带**（默认开，可选关）
- 位置：海拔剖面图下方（剖面关闭时贴画面底部，距底 60px）。
- x 轴复用剖面的 `plotLeft / plotW`，与剖面曲线**严格同一里程映射**。
- 高 14px（可调 4~40），圆角 3px，分段之间留 2px 空隙。
- 已走段实色，未走段同色 35% 不透明。
- 段内居中放 11~14px 中文路型名；太短（< 48px）则不写字，避免挤压。
- 条带与剖面游标同一个 x（共用 `cursorX`），不另算。

**第 3 层 · 当前路型芯片**（默认开）
- 胶囊形，显示「步道台阶 · 1.2 km」，路型切换时淡入换字（180ms）。
- 位置可选：跟随头部点（右上偏移）或右上 HUD 下方。
- 字号 18~20px，带 0.55 α 黑色描边保证暗底可读。

**可选第 4 层 · 图例**（默认关）
右下角竖排色块 + 名称，只列本次用到的路型。

## 3. 数据模型

### 3.1 参数

新增参数组 `路型`，键名沿用现有中文风格：

| 键 | 类型 | 范围 / 选项 | 默认 | 说明 |
|---|---|---|---|---|
| `显示路型` | bool | — | true | 总开关，关掉即回到现有单色线 |
| `路型分段` | text（专用编辑器） | JSON | `[]` | 分段定义，见 3.2 |
| `路型色相强度` | range | 0~1 / 0.02 | 0.85 | 0=只留纹理，1=满色 |
| `纹理密度` | range | 0.2~3 / 0.05 | 1 | 全局缩放纹理节距 |
| `已走同纹理` | bool | — | true | 关掉则已走段为纯色（旧观感） |
| `显示路型条带` | bool | — | true | 第 2 层 |
| `条带高度` | range | 4~40 / 1 | 14 | px |
| `条带标签` | bool | — | true | 段内写字 |
| `当前路型芯片` | bool | — | true | 第 3 层 |
| `芯片位置` | select | 跟随头部 / HUD 下方 | 跟随头部 | |
| `显示图例` | bool | — | false | 第 4 层 |

### 3.2 `路型分段` 格式

```json
[
  { "起": "老泉沟",           "止": "前往达西沟路口", "路型": "机耕路" },
  { "起": "前往达西沟路口",   "止": "老房子",         "路型": "步道台阶" },
  { "起": 1.42,               "止": 2.90,             "路型": "陡坡山路" },
  { "起": 2.90,               "止": "终点",           "路型": "攀爬" }
]
```

解析规则：
- `起` / `止` 为**字符串** → 先去 `自定义途经点` 里按 `名称` 精确匹配，取该点的里程。
- 为**数字** → 直接视为里程（km）。
- 特殊值 `"起点"` / `"终点"` / `0` / `null` → 0 或总里程。
- 匹配不到字符串 → **不静默丢弃**：在调参台编辑器里标红该行，出片时该段回落默认样式。
- 区间重叠：**后定义的覆盖先定义的**（数组中靠后的优先）。
- 未被任何分段覆盖的里程 → `默认路型`（内置 `"无"`，即保持现有单色线）。

### 3.3 内置路型表

`路型` 取值来自内置表，可后续扩展：`机耕路 / 土路 / 步道台阶 / 陡坡山路 / 攀爬 / 无`。
每个路型在 `trail-scene.mjs` 里是一份常量对象（名称、宽度权重、主色、纹理类型、纹理参数），调参台的选择项**从场景模型 import**，不另写一份（沿用 `WP_SHAPES` 的既有做法）。

## 4. 调参台 UI（`trail-studio.html`）

1. 新组「路型」放在「轨迹」组下方，组内顺序同 3.1 表。
2. `路型分段` 用专用编辑器（`ui: "roadtypes"`，仿现有 `ui: "waypoints"`）：
   - 列表行：`[起 ▾] → [止 ▾] · [路型 ▾] · [里程提示 1.04–1.42 km] · [删除]`
   - `起` / `止` 是下拉：选项 = `起点` + 所有已定义途经点名称 + `按里程…`（选中后出现数字输入框）。
   - 底部「+ 添加分段」；新增时默认「接上一段终点 → 终点」。
   - 实时校验：起止颠倒、区间重叠、名称不存在 → 行内红字提示，**不阻止保存**（避免打断调参）。
3. 编辑器下方一条**迷你预览条**（宽 100%，高 18px），实时按当前分段着色，改了立刻能看到覆盖关系。
4. 顶栏快捷开关加一个「路型」（与现有「海拔图」同级），只切 `显示路型`。

- 几何一律在 `trail-scene.mjs` 算，组件只按 `t` 建元素；调参台与出片共用同一函数。
- 所有纹理参数必须确定性，不用 `Math.random`。
- 台阶横杠的采样间距以**屏幕像素**为单位（除以 `k` 换算到用户坐标），否则缩放时会疏密跳变。

## 6. 验收标准

1. 1080p 抽帧（首 / 中 / 尾各一张），5 种纹理**不放大即可分辨**；相邻路型不用看颜色也能区分。
2. 走到某段后，该段纹理仍然可见（不是被白线盖住）。
3. 分段边界无缝隙、无叠色、无位置偏移（与未分段的原始 `trackPath` 逐点重合）。
4. 条带游标与剖面游标 x 完全相同（同一 `cursorX`）。
5. 关掉 `显示路型` 后，画面与当前版本**逐像素一致**（回归保护）。
6. 渲染耗时增幅 ≤ 20%（新增图元 < 400 个；不开光晕前提下）。
